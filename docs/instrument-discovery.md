# Automatic instrument discovery

The execution-profile map is no longer an allowlist for US stocks or ETFs. A new Bravos
ticker such as MEDP is looked up automatically, matched exactly, and checked
against live permissions on both the agent and owner accounts. Existing profiles
remain identity/product evidence overrides; no MEDP entry is needed in configuration.

The resolver requests the exact ticker and its `.US` alias, requires a complete
single match, and refuses ambiguous matches. Known aliases such as ETHA.US stay
pinned to their verified IDs to avoid the unrelated ETHA crypto ticker. A newly
resolved ID cannot duplicate a different configured/discovered source symbol.

For automatic setup the broker must classify the instrument as `Stocks`, or as
`ETF` when `allowLeveragedFunds` is true,
and its exchange directory must identify a supported US equity exchange. This
establishes the stock category and USD session context, rather than inferring
them from the ticker text. It selects a shared long X1 settlement with fixed-stop
support on both accounts, preferring real shares over CFD. Live permissions,
cash, costs, price and stop checks still run before submission. US holiday and
freshness rules apply. Metadata is rechecked within the invocation; durable
orders retain the exact instrument ID for reconciliation after restart.

Price comparisons use cents rounded downward and proportional reductions use
five decimal places, the same deliberate calculation granularity as existing
stock profiles. These are not claims of maximum broker precision. Exact stop
prices are never rounded. Selling existing shares does not require permission
to open a new position or request a fresh entry-cost estimate.

## Remaining coverage boundaries

This removes the per-ticker setup failure for US stocks and ETFs. It does not yet establish
automatic support for every eToro product. The long USD trading model remains;
shorts, futures contracts and currency conversion require different semantics.
Unknown product classes still need their execution/currency semantics established;
existing verified profiles continue to work. Foreign
stocks need a verified price currency/session. These are specific missing facts,
not a user portfolio-allocation decision or a reason to reject all new tickers.

On 23 September, after an explanation of daily amplified gains/losses, the owner
chose **"Allow them when Bravos recommends them"** for funds with embedded
leverage. `allowLeveragedFunds` is now true in the project configuration, false
by default elsewhere. This replaces the prior embedded-leverage prohibition for
funds only. Broker leverage remains X1. TQQQ's X1 eligibility does not make it
unleveraged: the broker's ETF classification is accepted under the revised product
policy. No independent purchase signal is generated by catalogue discovery.

Read-only MEDP discovery on 23 September returned `Medpace Holdings Inc.`,
instrument 8882, type Stocks, Nasdaq. Both accounts offered real long X1 with
fixed stops. No order was submitted during development.

API schemas: the captured official `state/etoro-openapi.json` documents
`GET /api/v2/market-data/instruments`, `GET /api/v1/market-data/exchanges` and
`POST /api/v2/trading/info/eligibility`. `gr instrumentAudit -Psymbols=MEDP`
refreshes the evidence; raw responses remain ignored.
